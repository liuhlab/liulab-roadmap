# 用 Claude Code 写这个网站

这个网站的每一页，包括你正在看的这一页，都是 Claude Code 起草、人来改出来的。值得写一写，倒不是因为这个网站本身有什么意思，而是这套分工很容易搬到你手上的活儿里，而且多数人第一次上手都会弄拧。

## 各自干什么

行得通的分工是：什么值得说、说得对不对，你来定；搭建的部分交给它。

这里一个页面的起点通常是几条要点加一个观点。Claude 把它变成初稿，中英文一起写，把页面接进导航，跑一遍构建，顺手修掉自己弄坏的地方。然后才开始真正要吵的部分，而这部分仍然是人的活儿：这个说法站得住吗？这段话读起来像人写的吗？

一个好用的心理模型是：一个手很快、不嫌任何杂活枯燥、但完全没有判断力的合作者。它交出来的每样东西都只是一份提案。

## 怎么把它接进项目

有几个习惯，决定了你得到的是一个真帮得上忙的 agent，还是一堆看着挺像回事的乱码。

把整个项目交给它，而不是粘贴片段。它会自己打开文件、检索、执行命令、读输出、再试一次。在聊天窗口里来回粘代码，等于把它大部分本事都扔掉了。

规矩写下来一次就好。每次会话都从零开始，上周定过的事这周会以另一种方式重新定一遍。这个仓库根目录有个 `CLAUDE.md`，agent 每次会话开始都会读它，里面放的就是那些不写下来就要反复交代的东西：中英文一起写、一个页面要能一口气读完、别用某种腔调。它大概一百行，是整个项目里性价比最高的一个文件。

让它自己验收。只要它能跑构建、能看到报错，它就会先改好再拿给你；做不到的话，你就成了那条报错信息。

## 一个让人觉得很值的例子

我们想给术语加悬停释义，这样读者第一次碰到"反向传播"这种词，不用离开页面就能看到一句话解释。结果发现常规做法在中文上根本不管用。

这种事平时就是想法夭折的地方。倒不是有多难，而是它离你真正坐下来要干的活有半天的距离，还只是个锦上添花的东西。最后它在一次会话里就做完了，现在全站每一页都有。

这才是 agent 比写文字更划算的地方。那些"不值得为它打断一次"的小改进，成本降到可以随手就做，项目于是慢慢变好，而这些改进本来是不会发生的。

## 哪些地方指望不上它

品味和事实。这里第一个正经页面在所有事实都核对无误之后，光语气就又改了两轮。而且它说错话时的笃定程度，和说对话时一模一样，所以审阅这一步没法省。剩下的活儿，大半就是审阅。

## 想在自己的项目上试试

有几点是我们摸出来的。从一个已经存在的代码库开始，比从空目录开始顺；让它改之前，先让它讲讲这些代码在干什么。同一句话说到第二遍，它就进 CLAUDE.md。改动没读过之前，不留下。

想看看"一百行攒下来的偏好"长什么样，这个网站的规则文件在 [CLAUDE.md](https://github.com/liuhlab/liulab-roadmap/blob/main/CLAUDE.md)。
