# Writing This Site With Claude Code

Every page on this site, including this one, was drafted by Claude Code and revised by a person. That is worth describing not because the site itself is interesting, but because the arrangement copies easily to whatever you are working on, and most people set it up wrong the first time.

## Who does what

The split that works: you decide what is worth saying and whether it is true, and the agent does the building.

A page here starts as a handful of bullet points and an opinion. Claude turns that into a draft, writes the Chinese version alongside the English one, hooks the page into the site navigation, runs the build, and fixes whatever it broke along the way. Then the arguing starts, and that part stays human. Is this claim actually correct? Does this paragraph sound like a person wrote it?

A useful way to hold it in your head is a fast, tireless collaborator who never finds a chore too boring and has no instinct for what matters. Everything it hands you is a proposal.

## Getting it into a project

A few habits separate an agent that earns its keep from one that produces plausible mess.

Give it the whole project instead of pasted snippets. It opens files on its own, searches, runs commands, reads the output, and tries again. Passing code back and forth through a chat window throws away most of what it can do.

Write your rules down once. A session begins with no memory of the previous one, so whatever you settled last week gets settled differently this week. This repository keeps a file called `CLAUDE.md` at its root that the agent reads at the start of every session. It holds the things you would otherwise explain forever: write both languages in the same pass, keep a page readable in one sitting, avoid this particular tone. It runs about a hundred lines, and pound for pound it is the most important file in the project.

Let it check its own work. Given a way to run the build and see the errors, it will fix them before showing you anything. Without one, you become the error message.

## One case that made the value obvious

We wanted hover definitions on jargon, so that a reader meeting a word like backpropagation for the first time gets a one-line explanation without leaving the page. The standard way of doing this turned out not to work on Chinese text at all.

That is normally where the idea dies. Not because it is difficult, but because it is a half-day detour away from the work you actually sat down to do, spent on something merely nice to have. Instead it got built in one session, and now every page on the site has it.

This is where an agent pays off more than it does on prose. Small improvements that were never worth the interruption become cheap enough to simply do, and a project slowly gets better in ways it otherwise would not have.

## Where it does not help

Taste and truth. The first real page here needed two full revision passes on tone alone, long after every fact in it was correct. The agent will also state something wrong with exactly the confidence it uses to state something right, so reviewing is not optional. That review is most of the work that remains.

## Trying it on your own project

A few things made the difference for us. Starting on a codebase that already exists rather than an empty directory, and asking it to explain the code before asking it to change any. A rule goes into CLAUDE.md the moment we catch ourselves saying the same thing twice. And nothing gets kept without being read first.

If you want to see what a hundred lines of accumulated preferences looks like, this site's rules file is [AGENTS.md](https://github.com/liuhlab/liulab-roadmap/blob/main/AGENTS.md).
